## What ContentTool is (settled today, wider than the original plan)

- A **dev-only mod DLL** (`Morgott.ContentTool`, `ct_*` commands) that both **adds** new content and
  **replaces** shipped content — everything ResourceReplacer could replace, plus what it never could.
- **Two modes, one codebase:**
  - **Developer workbench** — live swap while the game runs (Harmony seam + re-apply). Runtime cost OK.
  - **Shipping** — **ZERO runtime code**. User mandate, non-negotiable. Assets load natively.
- Released mods depend on neither ContentTool.dll nor ContentLib.dll.

## Shipping mechanism (route vii) — PROVEN in-game

Copy the player's own `<target>_assets_all.bundle`, patch the copy, repoint that bundle's
`m_InternalIds` in `StreamingAssets\aa\catalog.json` at the copy, zero its `m_Crc`. Game's own
Addressables then serve it. `Addressables.InitializeAsync` (PhoenixGame.cs:738) runs BEFORE
`InitMods()` (:758) → no mod can amend the catalog at runtime → the edit is on-disk, hence zero-runtime.

- Generated copies live in `persistentDataPath\ContentTool\Patched\<modid>\` — **never** in the mod
  folder (it may be a Steam-managed Workshop dir that Steam wipes).
- A published mod **cannot ship** the patched bundle (that would redistribute PP assets), so it ships
  sources + declaration and `ct_route7 apply` **bakes on the player's machine** when copies are absent.
- Multi-mod: `catalog.json.ct-backup` (PRISTINE, written once) + `catalog.json.ct-edits` (one line per
  mod). Every write **rebuilds from pristine + surviving lines** — so edits never stack on each other
  and reverting one cannot disturb another. Same-bundle conflict refuses and names the owner.
- The old ban on this was **policy, not physics**: §29.3 was misquoted (it is test hygiene, bans
  nothing); §10.1's only objection was patch fragility, which the user has explicitly waived
  ("patches don't ship; if one does, we update the mod").

## Working discipline (this is why the day worked)

- Every gate is **falsifiable**, with a **control in the same run**, and must be able to FAIL. A validator
  that never rejects proves nothing (that is why A4 exists).
- **A "permanently ruled out" row is only as wide as the run that produced it.** Audio was rejected in
  four places, all tracing to ONE runtime probe that structurally could not test a startup flag. Ask
  what a rejection actually MEASURED before treating it as a wall — re-testing this one cost three
  launches and deleted ~5-8 kLOC of planned decoder work. The counterpart of "check Permanently ruled
  out first" is "check what it measured", and both lessons come from the same row.
- **Silent skips are the enemy** — three separate ones today printed `ALL PASS` while the feature never
  ran. Always print counts including 0; a gate that cannot answer must say **VOID**, never PASS or FAIL.
- Oracles must not be fakeable: read the **name**, not null (both negative arms returned
  `Hidden/InternalErrorShader`); read the **size**, not pixels; read the **file**, not the engine API when
  a shaderless Material has no property sheet.
- Never record a fact that came from a run whose instrument was broken. Several numbers today were
  correctly withheld.
- **An Addressables probe key must be a catalog KEY** — the asset GUID or its address — never an
  `m_InternalIds` path. The path names the same entry and still resolves to null; P2 chased that for
  three runs. The mutoid probe hides it because there the path happens to be a key too.
- **Name lookups inside a bundle must refuse ambiguity.** `aln_fireworm` ships two Materials both
  called `ALN_Fireworm`; taking the first match would have patched an arbitrary one silently.
  `BundleBaker.FindUnique` now refuses zero AND more-than-one, which is §39.2's own rule.
- Agents: PowerShell only (never Bash), Serena for nav, Context7 for lib APIs. **Commit with an explicit
  pathspec** (`git commit -m "..." -- <paths>`) — parallel agents share one index and swept each other's
  work twice. Never `git add -A`. Commit body IS the report (agent messages get lost).
- **A fixture must not pick a FIXED POINT of the permutation it tests.** With 3 bones the MIDDLE slot
  is unchanged by a reversal, so a fixture that picks it measures NOTHING and reads green either way.
  Pick the FIRST and the LAST. (P6/R6.)
- **Grep the donor before writing a limitation down.** `SkinBinder` had been sitting in the tree with
  no caller (`src\Import\GlbReader.cs:1184`) while four documents recorded its absence as a ceiling.
- Ponytail ladder in every brief verbatim (subagents have no Skill tool). Measuring before building
  deleted a whole mechanism today (the entry-redirect variant died when LZ4 made the disk cost vanish).
