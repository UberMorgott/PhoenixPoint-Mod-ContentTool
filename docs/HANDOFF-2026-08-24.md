## What ContentTool is

The ENGINE mod for Phoenix Point. It builds real Unity AssetBundles **offline, with no Unity
Editor**, and lets other mods replace or add any content. Content mods depend on it, ship bundles,
and never modify original game files.

North star, the user's own words, treat as an acceptance criterion:

> The mod author drops files into the project folders by convention, runs ONE console command
> in-game, and gets a finished bundle. No Blender, no gltf-transform, no Unity, no npx. If a file
> needs an external tool, that is a ContentTool BUG, not the author's job.

## THE ANIMATION BRIDGE — how it actually works

This was the session's hardest research. Two mechanisms, and an earlier claim that "the game does
not name states or fire triggers" is TRUE for the continuous clip table and FALSE for one-shots.

1. **Continuous clips (nav, idle).** The game ships ONE `AnimatorController` per creature family
   and rewrites the CLIPS INSIDE IT — `TacticalActor.cs:724-726` →
   `AnimatorClipOverrides.CreateAnimatorClipOverrides` → `ActorAnimActions.Setup`. Which clip plays
   comes from `TacActorAnimActionsDef`, a list of TYPED anim actions. Exactly one action of each
   type carries `IsDefaultAnimatorClips=true` and **its clips are the override KEYS**
   (`TacActorAnimActions.cs:52-54`); every other action is a value set applied positionally
   (`:70-79`). **The def slots are keys INTO the controller, not what plays** — a key that is null
   or is not a clip inside the controller is silently dropped
   (`AnimatorClipOverrides.cs:27-31`), which is why filling more slots fixed nothing.
2. **One-shots are TRIGGERS.** `RagdollDieAbility.cs:92-95` does
   `Animator.SetTrigger("Die")` then waits for the `Ragdoll` anim event.
   `ActiveIdleClips.Death` is read at `:102` only to find a "Voice" event — it is never played.
   Also live: the `Reaction` trigger, the `Alert` bool, the `CoverType`/`TravelType` ints
   (`IdleAbility.cs:101-111`, `TacticalActorBase.cs:1109`).
   Death is NOT purely ragdoll: `RagdollDieAbility.cs:90-99` plays the Die state and waits for the
   event on a small impact; pure physics is only for a big hit.
- Anim events must be stamped or the game waits 10 s per action
  (`AnimEventReceiver.cs:116-127`). The demo stamps 4.
- The spider has 5 clips against 79 slots; walk covers 49 (incl. `Turn90`, `Turn180`,
  `TurnSequence`), idle 8, attack 18, jump 3, death 1.

## HOW TO WORK — rules that produced today's results

- **LEAD owns the single game install.** Subagents must NEVER launch Phoenix Point. LEAD runs
  `.\autogate.ps1` and reports the lines back. The game is single-instance PER INSTALL; a second
  launch dies with an empty log that looks like a mod failure.
- **Assign explicit file ownership** to every parallel agent and forbid `git add -A` — several
  sessions share this tree. Shared files (`docs\PROVEN-FOUNDATIONS.md`, csproj) are LEAD's;
  agents end their commit body with a `FOR PROVEN-FOUNDATIONS` section instead.
- **The commit body IS the report.** Agents go idle without messaging; read their work out of
  `git log`. Verify their claims yourself — run the suites, read the game log.
- **Never guess a serialization field, engine API or spec rule.** Ground it or STOP. Today a
  review guess (`m_AnimationType=2`) was measured FALSE — no such field exists on a 2019.4.31f1
  AnimationClip, and the Draco spec was found wrong or silent in five places.
- **Falsify every arm.** An arm that cannot fail measures nothing. Pick fixtures where a wrong
  implementation cannot coincidentally agree with a right one: nlerp and slerp agree exactly at the
  midpoint (so sample a quarter of the arc); the two dense-bank interleaves agree at frame 0 of
  binding 0 (so compare a middle frame of a late binding); an octahedral fold is a no-op across the
  whole upper hemisphere (so assert the fixture contains folded normals).
- **The dominant failure is the arm that is more tolerant than the game.** `C1-rig` used
  `GetComponentInChildren` where the game uses `GetComponent`, so it could not see the bug that
  blanked the model. Assert the OUTCOME, with the same strictness the engine uses.
- **Codex is the second reviewer.** `codex exec review --commit <sha> -o out.md` (see the Codex
  section of the global CLAUDE.md). Today it found 12 real defects, 0 false — including a rifle
  shipped inside-out and three gates that could pass vacuously. Verify each finding before fixing:
  twice it named the right defect class and the wrong location or an insufficient remedy.

### Commands

```powershell
dotnet run --project tests\ObjCodecTests\ObjCodecTests.csproj -c Release
dotnet run --project tests\TargetPathTests\TargetPathTests.csproj -c Release
.\deploy.ps1                     # builds, ILRepacks, installs the mod AND all demos
.\autogate.ps1 -Commands 'ct_project CustomCreature'      # LEAD only
.\autogate.ps1 -Commands 'ct_route7 apply WeaponMesh' -Then 'ct_route7 status'
```

`autogate.ps1` refuses to start if the game is already running from that root, only ever kills the
PID it launched, and verifies the loaded DLL's SHA-1 so a stale build cannot report ghost lines.
