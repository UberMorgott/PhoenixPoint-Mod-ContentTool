# u8_rootfold.glb — source and licence

Gate **U8**'s HARD case, read straight off disk by `tests\ObjCodecTests\SkinAbove.cs` (`Hard()`);
**not** embedded in the assembly, so it costs the shipped mod nothing.

- **Origin:** GENERATED by this project — no download, no third-party asset, nothing to licence.
  Written once by a throwaway PowerShell script that emits the glTF container, the bufferViews and
  the accessors by hand (the same spelling `tests\ObjCodecTests\ClipImport.cs` uses in memory), so
  no line of `GlbCodec` — this repo's own writer — takes part. That is the point: every coordinate
  rule the writer and the reader share is an INVOLUTION, so a round trip through our writer would
  survive both halves being wrong together. 2 176 B.
- **Why it exists:** the shape a real Blender export has and no other fixture in this repo carried —
  an armature OBJECT with a NON-IDENTITY transform (−90° about X **and** a scale of 100) whose ROOT
  bone is driven by animation, on a skinned mesh. `lib\u8_probe.glb` has the transform but no curve
  on its root bone; `SkinAbove.RootCurve`'s in-memory fixture has a curve on the root but only a
  SCALE above it and only a translation channel. Neither exercised a rotating fold composed with a
  rotating curve.

## Contents, in full — every number the arm asserts is derived from this list by hand

| node | name | transform |
|---|---|---|
| 0 | `CtArmature` | rotation `[-0.70710678,0,0,0.70710678]` (−90° about X), scale `[100,100,100]`, child 1 |
| 1 | `Root` | none — `skins[0].joints[0]`, child 2 |
| 2 | `Child` | translation `[0,1,0]` — `skins[0].joints[1]` |
| 3 | `Body` | `mesh:0`, `skin:0` |

- **Mesh** `rootfold`: one triangle, POSITION `(0,0,0) (1,0,0) (0,2,0)`, NORMAL `(0,0,-1)` ×3,
  JOINTS_0 `0 / 0 / 1`, WEIGHTS_0 `1` — so vertices 0 and 1 hang on `Root` and vertex 2 on `Child`.
- **Inverse bind matrices**, armature-object-LOCAL (which is what Blender writes — see
  `SkinAbove`'s class remark): `Root` identity, `Child` translate `(0,-1,0)`.
- **Animation** `RootDrive`, both samplers LINEAR on key times `0` and `1` s, both driving **node 1,
  the root bone**: translation `(1,0,0) -> (5,0,0)`, rotation identity `-> (0,0.70710678,0,0.70710678)`
  (+90° about glTF +Y).
- The first translation key is deliberately the file's **own vertex 1**, so the arm can assert that
  the sample and the baked vertex land on the SAME Unity coordinate rather than on two constants.
